# ТЗ: надёжная связь Mac ↔ телефон по SFTP

Ты — инженер, который чинит связь MacDroid Commander с Android-телефонами. Проект: `/Users/restart/Documents/GitHub/MacDroidCommander`. Mac-приложение — `MacHost/` (Swift), компаньон на телефоне — `AndroidCompanion/` (Kotlin, встроенный сервер Apache MINA SSHD, порт 2222). Mac подключается системным `/usr/bin/ssh`.

Задание состоит из трёх независимых частей: A (Mac), B (Android), C (сопряжение). Каждую часть ведёт один агент. Выполняй свою часть целиком, с проверкой на реальном телефоне.

## Что установлено проверкой 9.11.2026

Подробности и выдержки кода — в `/Users/restart/Documents/GitHub/MacDroidCommander/docs/discussions/2026-11-09-connection/` (три файла). Ниже только итог и то, что добавилось после них.

### 1. Приложение на Mac не видит телефон, который доступен (главная причина сейчас)

Состояние в 23:10: Xiaomi на `192.168.1.16:2222`.

- Из Терминала: порт открыт, Bonjour `_macphone_sftp._tcp` виден, ключ телефона совпадает с закреплённым, вход ключом `~/.ssh/macdroid_id_ed25519` проходит за 0,3 с.
- Приложение 2.1.325 (запущено в 19:15:59, подписано постоянным локальным сертификатом) с 19:18:45 не подключено, хотя у телефона включено автоподключение.
- За 60 с наблюдения приложение ни разу не запустило `ssh-keyscan`. Значит, его проба порта `NetworkPortReachability.isPortOpen` для `192.168.1.16` возвращает «закрыт».
- За 40 с в `lsof` у приложения видны только соединения в `SYN_SENT` к старым адресам из других сетей (`192.168.68.64`, `10.171.79.23`). Соединение к `192.168.1.16` не появляется ни разу: `connect()` завершается сразу.

Вывод: macOS не пускает сам процесс приложения в локальную подсеть (разрешение «Локальная сеть»), а Терминал и уже открытые соединения дочернего `ssh` — пускает. Постоянная подпись (2.1.326) это не исправила: приложение подключилось сразу после запуска и потеряло доступ через минуты. `errno` пробы не измерен — код его не сохраняет.

### 2. Сессии рвутся по молчанию телефона

С 5.11 большинство обрывов — `Timeout, server … not responding` (18 из 26). На Mac стоит `ServerAliveInterval=10`, `ServerAliveCountMax=2`: 20 секунд тишины закрывают сессию. В журнале сервера на телефоне в эти моменты нет ни перезапуска, ни смены адреса (например, 8.11 с 19:49 до 22:59 — семь обрывов, сервер работал без перерыва). Компаньон держит WakeLock и WifiLock только во время передачи, поэтому простаивающая сессия не переживает сон Wi-Fi. Это вероятная причина, не измеренная.

### 3. Телефон уходит в другую сеть

Xiaomi несколько раз в день переходит между `192.168.1.x` (сеть Mac) и `192.168.68.x` (вторая сеть в доме), а вне дома — в сети `10.x`, `172.x`. 9.11 с 20:16 до 22:24 он был вне сети Mac. Пока телефон в другой сети, связи нет при любом коде. Приложение этого не объясняет и продолжает опрашивать старые адреса чужих подсетей.

### 4. Обрыв 19:18:45 во время передачи

`Broken pipe` через 2,5 минуты после начала отправки файла 6,6 МБ. Сервер на телефоне в это время не перезапускался и адрес не менял (журнал: записи 18:30 и затем 20:16). Причина не установлена.

### 5. Ложные перезапуски сервера и отказ в сопряжении

- Самопроверка компаньона перезапускала сервер 6–7.11 четыре раза («проба порта не прошла»); перезапуск рвёт активные сессии.
- После переустановки компаньона телефон отвечал `Permission denied`, а окно сопряжения не принимало ключ, потому что `authorized_keys` был не пуст. Пользователь видел сетевую ошибку.

### Чего в журналах нет

`~/Library/Logs/MacDroidCommander/transport.log` пишет только завершение процессов `ssh`. Попытки автоподключения, результаты проб и причины отказа не записываются, поэтому пункт 1 пришлось восстанавливать через `lsof` и `ps`.

## Часть A. Mac: доступ к локальной сети и диагностика

Файлы: `MacHost/Sources/MacHostCore/Transport/` (`NetworkPortReachability.swift`, `PhoneConnectionManager.swift`, `ConnectionController.swift`, `DiscoveryService.swift`, `SSHTransportLog.swift`), `scripts/build_macos_app.sh`.

1. **Журнал попыток.** Писать в `transport.log`: каждую пробу адреса (адрес, результат, `errno`, длительность), состояние `NWBrowser` (включая `.waiting` и код ошибки), решение автоподключения (подключаюсь / пауза / пропуск и почему). Одна строка на событие, без повторов чаще раза в минуту для одного и того же результата.
2. **Измерить запрет.** С этим журналом воспроизвести пункт 1 и записать `errno` пробы и ошибку `NWBrowser` в момент, когда Терминал телефон видит, а приложение нет. Проверить, восстанавливается ли доступ после перезапуска приложения и через сколько пропадает.
3. **Устранить причину.** По результату шага 2 добиться, чтобы приложение, собранное `scripts/build_macos_app.sh`, держало доступ к локальной сети дольше суток и после пересборки. Проверить и учесть: старые записи «MacDroid Commander» и «MacHost» в «Настройки → Конфиденциальность и безопасность → Локальная сеть» от копий с ad-hoc подписью; запуск из разных путей; запуск агентами из Терминала. Если причина не в разрешении — исправить найденную.
4. **Обход через дочерний процесс.** Если запрет действует только на процесс приложения, а `ssh-keyscan` и `ssh` проходят, заменить внутреннюю пробу на ту, что проходит, и не требовать успеха внутренней пробы перед запуском `ssh`. Сначала проверить это измерением.
5. **Сообщение пользователю.** Различать три состояния и показывать разный текст: «macOS не даёт приложению доступ к локальной сети» (с указанием, где включить), «телефон в другой сети Wi-Fi» (адреса вне подсети Mac), «телефон не отвечает».
6. **Старые адреса.** В фоновом поиске не опрашивать адреса вне текущих подсетей Mac.

Готово, когда: приложение, оставленное запущенным на сутки, подключается к телефону в сети Mac без ручных действий; при каждом отказе в `transport.log` есть причина; три состояния из пункта 5 различимы в интерфейсе.

## Часть B. Android: сервер не теряет простаивающие сессии

Файлы: `AndroidCompanion/app/src/main/kotlin/com/macandroid/filemanager/runtime/FileDaemonService.kt`, `.../server/EmbeddedServer.kt`, `AndroidCompanion/app/src/main/AndroidManifest.xml`; на Mac — параметры keepalive в `MacHost/Sources/MacHostCore/Transport/SessionCoordinator.swift` (строки с `ServerAlive`).

1. **Журнал сессий.** В `daemon.log` писать открытие и закрытие каждой SSH-сессии (адрес клиента, причина закрытия, длительность), взятие и отпускание блокировок, а при провале самопроверки — число активных сессий и `PowerManager.isDeviceIdleMode`.
2. **Измерить обрывы по молчанию.** Держать простаивающую сессию с Mac при погашенном экране телефона 30 минут; сопоставить `transport.log` и `daemon.log`. Установить, что именно молчит: радио, процесс или сервер.
3. **Устранить.** Держать WifiLock, пока открыта хотя бы одна сессия, а не только во время передачи. Подобрать keepalive на Mac так, чтобы сон Wi-Fi не закрывал сессию, а настоящий уход телефона обнаруживался не дольше чем за минуту. Проверить расход батареи телефона за час простоя с открытой сессией.
4. **Самопроверка без вреда.** Не перезапускать сервер, если есть активные сессии или подключение принималось за последнюю минуту.
5. **Тип службы.** `dataSync` на Android 14+ ограничен шестью часами в сутки. Проверить по `daemon.log` и `ApplicationExitInfo`, останавливается ли служба по этому лимиту, и при необходимости сменить тип.
6. **Обрыв 19:18:45.** С журналом из шага 1 повторить отправку файла 5–10 МБ на телефон десять раз подряд; найти причину `Broken pipe`, если он повторится.

Готово, когда: простаивающая сессия живёт час при погашенном экране; десять передач подряд проходят без обрыва; за сутки в `daemon.log` нет перезапусков сервера при активных сессиях.

## Часть C. Сопряжение после переустановки компаньона

Файлы: `AndroidCompanion/app/src/main/kotlin/com/macandroid/filemanager/server/EmbeddedServer.kt` (`publickeyAuthenticator`), экран сопряжения компаньона; на Mac — `MacHost/Sources/MacHostCore/Transport/ConnectionController.swift`, `HostKeyStore.swift`, `ClientKeyManager.swift`.

1. Открытое окно сопряжения принимает новый ключ Mac и при непустом `authorized_keys`: один ключ за окно, с подтверждением на экране телефона, где виден отпечаток ключа Mac.
2. Экран компаньона показывает число сохранённых ключей и причину последнего отказа.
3. Mac отличает `Permission denied` от сетевой ошибки и показывает: «Телефон не знает этот Mac — откройте сопряжение на телефоне».
4. Смену ключа телефона после переустановки Mac проводит одним шагом: показывает новый отпечаток для сверки, затем сразу сопряжение.
5. Оставить на Mac один клиентский ключ вместо двух (`~/.ssh/macdroid_id_ed25519` и `client_ed25519.key`), не теряя уже сопряжённые телефоны.

Готово, когда: после удаления и установки компаньона связь восстанавливается за один проход по подсказкам на Mac и телефоне, без кнопки «Сбросить сопряжение».

## Общие правила

- Порядок: часть A первой — без неё результат остальных не виден в приложении. B и C можно вести параллельно с A: A меняет только `MacHost/…/Transport` и скрипт сборки, B — службу и сервер компаньона плюс две строки keepalive, C — аутентификатор, экран сопряжения и логику доверия на Mac. Общий файл B и C — `EmbeddedServer.kt`: B не трогает `publickeyAuthenticator`, C трогает только его.
- В основном чекауте есть чужие незакоммиченные правки интерфейса (`MacHost/Sources/MacHostCore/UI/…`, `MacHost/Tests/MacHostTests/main.swift`). Не изменять и не откатывать их; коммитить только свои файлы.
- Сначала измерение, потом правка. Гипотезы из раздела «Что установлено» помечены как вероятные там, где измерения нет.
- Проверка Mac: `cd /Users/restart/Documents/GitHub/MacDroidCommander/MacHost && swift run MacHostTests && swift run TransportRegressionTests`, затем `/Users/restart/Documents/GitHub/MacDroidCommander/scripts/build_macos_app.sh` (скрипт сам поднимает версию) и проверка на телефоне.
- Проверка Android: `/Users/restart/Documents/GitHub/MacDroidCommander/scripts/build_android_apk.sh`; поднять `versionCode` и `versionName` в `AndroidCompanion/app/build.gradle.kts`; обновлять компаньон поверх установленного, без удаления, чтобы не потерять ключи.
- На Xiaomi (HyperOS 3) включение «Отладки по USB» перезагружает телефон в отдельный профиль без компаньона. Журнал телефона читать по SFTP: `/emulated/0/Android/data/com.macandroid.filemanager/files/daemon.log`.
- Каждое изменение поведения — строка в `/Users/restart/Documents/GitHub/MacDroidCommander/CHANGELOG.md` и правка `/Users/restart/Documents/GitHub/MacDroidCommander/README.md`, если меняется то, что видит пользователь.
- В отчёте: версия приложения и компаньона, что измерено (с выдержками журналов), что изменено, что осталось непроверенным.
